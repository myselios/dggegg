# 토스 스타일 전면 적용 + 성능 개선 계획

작성: 2026-07-13. 목표: (1) 대시보드 목업으로 확정한 토스 스타일을 앱 전체에 적용, (2) 상단 헤더 → **사이드바** 내비 전환, (3) 템플릿 등 느린 화면 및 전반적 성능 개선. 주 사용 환경은 **PC**. 다크모드 제외(사용자 결정).

---

## A. 성능 개선 (먼저 진행 — 근본 원인 진단 완료)

### A-1. 템플릿/자료/학생상세 느림 — 서버 블로킹 → 클라이언트 SWR 전환 ★
**진단:** `/templates`, `/materials`, `/students/[id]`는 서버 컴포넌트가 진입 시마다 `await get…()`(requireAuth 쿠키 + Supabase 쿼리)를 **서버 왕복으로 대기**한 뒤 렌더한다. 클라이언트 캐시가 없어 재방문에도 매번 재조회. (학생/스케줄/대시보드는 이미 SWR로 캐싱되어 빠름 — 이 격차가 "템플릿만 느린" 이유.)

**조치:** 학생 페이지의 `useStudents` 패턴을 그대로 복제.
- `lib/hooks/use-templates.ts`, `use-materials.ts` 신규 (SWR + supabase 클라이언트)
- `/templates`, `/materials` 페이지를 **정적 클라이언트 셸**로 전환 → CDN 즉시 서빙 + 링크 prefetch + SWR 캐시(재방문 즉시 표시, 백그라운드 갱신)
- `/students/[id]`는 이미 있는 `useStudent(id)` 훅으로 클라이언트 전환
- 기존 loading.tsx 스켈레톤은 최초 1회에만 노출

**효과:** 탭 전환 체감 지연 제거(서버 왕복 → CDN 셸 즉시), 재방문 즉시.

### A-2. backdrop-filter(글래스) 제거로 런타임 부담 완화
`blur(16px)` glass-card가 33개 파일에 적용 → 스크롤·상호작용 시 GPU 리페인트 비용. 토스 리디자인(불투명 카드)으로 **자연 해소**. B-1 토큰 교체가 곧 성능 개선.

### A-3. 부차 최적화
- SWR에 `keepPreviousData` 추가(전환 시 이전 데이터 유지 → 깜빡임 감소)
- `useIsMobile`가 서버에서 false 반환 → 데스크톱 먼저 그렸다 모바일서 전환되는 플래시. 사이드바 전환(B-2) 시 CSS 미디어쿼리 기반으로 바꿔 JS 분기 자체 축소
- 프로덕션 이미지/아이콘은 이미 정적. 추가 번들 분석은 후순위

## B. 토스 디자인 시스템 전면 적용

### B-1. 디자인 토큰 교체 (globals.css) — 최고 레버리지
토큰만 바꾸면 전 화면이 한 번에 토스 계열로 이동. 컴포넌트는 토큰을 참조하므로 대량 수정 불필요.
- **액센트**: 인디고 → 토스 블루 `oklch(0.62 0.19 250)` (#3182F6 계열)
- **표면**: 반투명 glass-card(`oklch(1 0 0 / 65%)` + blur) → **불투명 흰 카드** + 얇은 그림자 한 겹
- **배경**: glass-mesh 그라데이션 → 차분한 쿨그레이 `#F2F4F6`
- **의미색 분리**: good=초록, warn=주황, danger=토스레드 `#F04452` (액센트 블루와 별개)
- **타이포**: 숫자 tabular-nums + 굵게, 라벨 그레이 `#8B95A1`
- radius/Geist 폰트는 유지

### B-2. 사이드바 내비 전환
- 데스크톱: `Header`(상단) → `Sidebar`(좌측 고정 220px). `Sidebar` 컴포넌트는 이미 존재 → 토스 스타일(불투명 흰, 블루 액티브 pill, 하단 프로필)로 갱신하고 `mobile-layout.tsx`가 데스크톱에서 이를 렌더
- 모바일: 기존 하단 탭 바 유지
- 라벨 정리("Dashboard"→"대시보드" 등)

### B-3. 화면별 폴리시 (토큰 교체 후 순차)
| 순위 | 화면 | 작업 |
|---|---|---|
| 1 | 대시보드 | 목업대로 통계 타일 큰 숫자·완료율 바차트·정산/상담 레일 (bento 뼈대 재활용) |
| 2 | 학생 목록(표 모드) | 토스형 테이블(선명 행·hover·큰 숫자), 카드뷰도 정리 |
| 3 | 스케줄 | 캘린더 블록 대비 강화, 오늘 열 강조, 글래스 제거 |
| 4 | 학생 상세 | 탭·프로필·성적 차트 토스형(큰 숫자, 선명 카드) |
| 5 | 자료/템플릿 | 카드 목록 정돈, 큰 터치 영역 |
| 6 | 수업노트/다이얼로그 | 입력 폼 토스형(큰 인풋·명확한 1차 버튼) |

### B-4. 공통 컴포넌트 정리
`components/ui/*`(button, card, dialog, input 등)의 기본 스타일을 토스 토큰에 맞춤 → 화면별 작업량 최소화.
